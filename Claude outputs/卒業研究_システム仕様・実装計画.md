## 1. 研究内容

### 1.1 背景
現実の分類データでは、クラスごとの件数が均等とは限らない。少数クラス（例：契約した顧客、高所得者、不正取引）は件数が少なく、モデルが多数クラスばかり予測してしまうことがある。このとき Accuracy は高く見えても、少数クラスはほとんど当たっていない。

### 1.2 目的
1. 学習データの量が予測性能に与える影響を明らかにする
2. クラス不均衡の度合いによって、少数クラスの予測性能がどう変わるかを分析する
3. データ量と不均衡の組み合わせによる影響を比較する
4. 少数クラスを適切に予測するためのデータ量・比率の目安を考察する

### 1.3 リサーチクエスチョン
| No | 問い | 主に見る指標 |
|---|---|---|
| RQ1 | 学習データ量が増えると、少数クラスの Recall・F1 はどう変化するか | Recall, F1 |
| RQ2 | 不均衡が強いとき、Accuracy と Recall はどれだけ食い違うか | Accuracy, Recall |
| RQ3 | データ量と不均衡では、どちらの影響が大きいか | F1, PR-AUC |
| RQ4 | ロジスティック回帰とランダムフォレストで、不均衡への強さは違うか | Recall, F1 |
| RQ5 | どの程度のデータ量・比率なら少数クラスを実用的に予測できるか | F1, PR-AUC |

### 1.4 研究のゴール（完成の定義・企画書より）
1. データ量とクラス不均衡の条件を変えて実験できるプログラムが完成している
2. 2種類のモデルで、複数条件の予測性能を比較できる
3. 結果を CSV に保存し、評価指標をグラフ化できる
4. 少数クラスの Recall・F1 を中心に影響を分析している
5. 論文・発表スライド・実験コードがそろっている

## 2. 実験設計

### 2.1 データセット
| 項目 | Bank Marketing（既定・推奨） | Adult（代替） |
|---|---|---|
| UCI ID | 222 | 2 |
| 件数 | 約45,000件 | 約49,000件 |
| 目的変数 | `y`（yes / no） | `income`（>50K / <=50K） |
| 少数クラス（陽性=1） | `yes`（約12%） | `>50K`（約24%） |
| 注意点 | `duration` は結果判明後の情報なので除外する | ラベルに `>50K.` のように末尾ピリオド付きの表記揺れがあるので統一する |

※ 件数・比率はデータ取得後に `src/eda.py` で実測し、本書を更新する。
※ 既定は Bank Marketing。設定で Adult に切り替えられるようにする（未確定事項 Q1）。

### 2.2 変える条件（独立変数）
| 条件 | 値 |
|---|---|
| 学習データ量 `n_train` | 500 / 1,000 / 2,000 / 5,000 |
| 少数クラス比率 `minority_ratio` | 0.50 / 0.30 / 0.10 / 0.05 / 0.01 |

### 2.3 固定する条件（統制変数）
- テストデータ：全データの30%を `stratify` 付きで最初に分割し、以後一切変更しない（元のクラス比率のまま）
- 前処理：数値列は StandardScaler、カテゴリ列は OneHotEncoder（`handle_unknown="ignore"`）。前処理は学習データだけで fit する（Pipeline で担保）
- ハイパーパラメータ：各モデル固定（2.4）
- 分割の乱数：`split_seed = 42`

### 2.4 モデル
| 名前 | クラス | 固定パラメータ |
|---|---|---|
| `logreg` | `LogisticRegression` | `max_iter=1000`, `random_state=seed` |
| `rf` | `RandomForestClassifier` | `n_estimators=200`, `random_state=seed`, `n_jobs=-1` |

拡張（任意・既定オフ）：`class_weight="balanced"` を付けた `logreg_bal` / `rf_bal`。不均衡への対策として比較できる。

### 2.5 繰り返し
- `seeds = [0, 1, 2, 3, 4]`（5回）。シードはサブサンプリングとモデルの `random_state` の両方に使う
- 条件ごとに平均と標準偏差を求める

### 2.6 評価指標（すべて少数クラス＝陽性 1 基準）
| 指標 | 関数 | 備考 |
|---|---|---|
| Accuracy | `accuracy_score` | 不均衡で過大に見えることを示す比較用 |
| Precision | `precision_score(zero_division=0)` | |
| Recall | `recall_score(zero_division=0)` | 主指標 |
| F1 | `f1_score(zero_division=0)` | 主指標 |
| PR-AUC | `average_precision_score`（`predict_proba` の陽性確率） | 閾値に依存しない補助指標 |
| Balanced Accuracy | `balanced_accuracy_score` | 補助指標 |
| 混同行列 | `tn, fp, fn, tp` | CSV に4列で保存 |

### 2.7 実験規模
2モデル × 4データ量 × 5比率 × 5シード = **200回**（拡張込みで400回）。表形式の小規模データなので、一般的なノートPCで数分〜十数分の見込み。

## 3. システム要件

### 3.1 機能要件
| ID | 要件 |
|---|---|
| F1 | UCI からデータを取得し、`data/raw/` に CSV でキャッシュする。2回目以降はキャッシュから読む（オフライン実行可） |
| F2 | 前処理（不要列除去、ラベルの 0/1 化、欠損値処理）を行う |
| F3 | 学習／テストを固定シードで分割する |
| F4 | 学習データから、指定した件数・少数クラス比率のサブセットを抽出する。作れない条件はスキップしてログに残す |
| F5 | 2モデルを学習し、2.6 の指標を計算する |
| F6 | 1行＝1実験として結果を CSV に保存する |
| F7 | 全条件をまとめて実行する CLI を提供する。`--quick` で縮小条件（1分以内）を実行できる |
| F8 | 結果 CSV を集計し、平均・標準偏差の表とグラフ（PNG）を出力する |
| F9 | データの概要（件数・列・欠損・クラス比）を表示する EDA スクリプトを提供する |

### 3.2 非機能要件
- 再現性：同じ設定・同じシードなら同じ結果になる
- 実行環境：Windows 11 / Python 3.11 または 3.12 / VS Code。追加ライブラリは 3.3 のみ
- 実行時間：本実験は30分以内、`--quick` は1分以内
- 可読性：卒業研究として説明できるよう、関数ごとに日本語の docstring を付ける
- グラフの日本語表示：Windows のフォント（`Yu Gothic` → `MS Gothic` の順に試す）を設定する
- 発表時の「実機説明」で `--quick` → グラフ生成までを実演できる

## 5. モジュール仕様

### 5.1 `src/config.py`
```python
@dataclass(frozen=True)
class ExperimentConfig:
    dataset: str = "bank"                # "bank" | "adult"
    test_size: float = 0.3
    split_seed: int = 42
    train_sizes: tuple[int, ...] = (500, 1000, 2000, 5000)
    minority_ratios: tuple[float, ...] = (0.50, 0.30, 0.10, 0.05, 0.01)
    seeds: tuple[int, ...] = (0, 1, 2, 3, 4)
    models: tuple[str, ...] = ("logreg", "rf")

QUICK_CONFIG = ExperimentConfig(
    train_sizes=(500, 2000), minority_ratios=(0.50, 0.10), seeds=(0,))

DATASETS = {
    "bank":  {"uci_id": 222, "target": "y",      "positive": "yes",  "drop": ["duration"]},
    "adult": {"uci_id": 2,   "target": "income", "positive": ">50K", "drop": []},
}
```

### 5.2 `src/data.py`
| 関数 | 仕様 |
|---|---|
| `load_raw(name: str) -> pd.DataFrame` | `data/raw/{name}.csv` があれば読む。なければ `ucimlrepo.fetch_ucirepo(id=...)` で取得し、特徴量と目的変数を結合して保存してから返す |
| `preprocess(df, name) -> tuple[pd.DataFrame, pd.Series]` | `drop` 列を除去。目的変数の前後空白と末尾の `.` を除去し、`positive` と一致すれば 1、それ以外 0。カテゴリ列の欠損は文字列 `"missing"`、数値列の欠損は Pipeline 内で中央値補完 |
| `split(X, y, cfg) -> X_train, X_test, y_train, y_test` | `train_test_split(test_size, stratify=y, random_state=split_seed)` |
| `feature_types(X) -> tuple[list[str], list[str]]` | 数値列とカテゴリ列の名前リストを返す |

### 5.3 `src/sampling.py`
```python
def make_subset(X: pd.DataFrame, y: pd.Series, n_total: int,
                minority_ratio: float, seed: int) -> tuple[pd.DataFrame, pd.Series] | None:
```
- 少数クラス件数 `n_min = max(1, round(n_total * minority_ratio))`、多数クラス件数 `n_maj = n_total - n_min`
- どちらかが利用可能件数を超える場合は `None` を返す（呼び出し側でスキップ・ログ）
- `numpy.random.default_rng(seed)` で非復元抽出し、結合後にシャッフルして返す
- 戻り値の件数は必ず `n_total`、陽性件数は必ず `n_min`

### 5.4 `src/models.py`
```python
def build_model(name: str, num_cols: list[str], cat_cols: list[str], seed: int) -> Pipeline:
```
- 前処理：`ColumnTransformer([("num", Pipeline([SimpleImputer("median"), StandardScaler()]), num_cols), ("cat", OneHotEncoder(handle_unknown="ignore"), cat_cols)])`
- `name` は `logreg` / `rf` / `logreg_bal` / `rf_bal`。未知の名前は `ValueError`

### 5.5 `src/evaluate.py`
```python
def evaluate(model: Pipeline, X_test, y_test) -> dict[str, float]:
```
- 2.6 の全指標と `tn, fp, fn, tp`、`pred_pos_rate`（陽性と予測した割合）を返す

### 5.6 `src/run_experiment.py`（CLI）
```
python -m src.run_experiment [--quick] [--dataset bank|adult] [--with-balanced] [--out PATH]
```
- データ読込 → 分割（1回だけ）→ モデル × データ量 × 比率 × シードのループ
- 各実験で学習時間（秒）も計測
- 既定の出力先：`results/results_{dataset}_{YYYYMMDD-HHMM}.csv`（上書きしない）。`--quick` は `results/quick_*.csv`
- スキップした条件、総実行時間、ライブラリのバージョンを標準出力と `docs/experiment_log.md` に追記
- 進捗を `[12/200] rf n=2000 ratio=0.10 seed=3 f1=0.412` の形式で表示

**結果 CSV の列（この順）**
```
dataset, model, n_train, minority_ratio, seed,
n_train_pos, n_test, n_test_pos,
accuracy, precision, recall, f1, pr_auc, balanced_accuracy,
tn, fp, fn, tp, pred_pos_rate, fit_seconds
```

### 5.7 `src/analyze.py`（CLI）
```
python -m src.analyze --input results/results_bank_xxxx.csv
```
- `results/summary_{元ファイル名}.csv`：`model, n_train, minority_ratio` ごとの各指標の mean / std
- `figures/` に出力するグラフ（PNG、dpi=200、ファイル名は英数字）

| ファイル | 内容 | RQ |
|---|---|---|
| `line_recall_by_ratio_{model}.png` | 横軸＝少数クラス比率（対数軸・降順）、縦軸＝Recall、線＝データ量、誤差棒＝std | RQ1, RQ2 |
| `line_f1_by_ratio_{model}.png` | 同上で F1 | RQ1, RQ3 |
| `line_f1_by_size_{model}.png` | 横軸＝データ量、縦軸＝F1、線＝比率 | RQ1, RQ3 |
| `heatmap_f1_{model}.png` | 行＝比率、列＝データ量、値＝F1平均（注記付き） | RQ3, RQ5 |
| `acc_vs_recall_{model}.png` | 比率ごとに Accuracy と Recall を並べた折れ線（n=最大） | RQ2 |
| `model_compare_f1.png` | 2モデルの F1 を比率ごとに比較（n=最大） | RQ4 |

- 軸ラベル・タイトルは日本語。同じ指標のグラフは縦軸範囲を 0〜1 にそろえる

### 5.8 `src/eda.py`（CLI）

### 5.9 `src/check_env.py`
- Python と各ライブラリのバージョンを表示し、iris で LogisticRegression を学習して精度を表示。日本語フォントが見つかったかも表示
